# System Architecture

The **DORA Metrics Analyzer** project is designed using a client-server architecture, with an AI-driven approach for analyzing code repository data.

## Main Components

### 1. Backend (Python / FastAPI)
The backend acts as the orchestration and service exposure layer.
- **Framework:** FastAPI. Chosen for its high performance, native support for asynchronous operations, and ease of creating REST APIs.
- **AI Agent (`dora_metrics.agent`):** Uses LangChain and Google's `gemini-2.5-flash` model. The agent is configured with a specific prompt (DevOps analyst) and has access to "Tools" to make queries to GitHub.
- **GitHub Tools (`dora_metrics.tools.github_tools`):** Functions that use `PyGithub` to extract:
  - Recent Pull Requests.
  - Recent Releases.
  - Issues (to identify bugs and calculate MTTR/CFR).
- **Response Streaming:** The `/api/analyze/stream` endpoint uses Server-Sent Events (SSE) to send the LLM's thinking process to the client in real-time as tokens are generated.

### 2. Frontend (React / Vite)
The user interface is designed to provide a rich and interactive experience.
- **Framework:** React with Vite as a bundler (for rapid development).
- **Data Visualization:** `recharts` is used to display charts (e.g., Deployment Frequency over time).
- **Markdown Processing:** `react-markdown` is used to render the detailed report generated by the AI in a presentable way.
- **Exporting:** `html2pdf.js` is used to allow exporting the reports to PDF format.

### 3. Local Storage
- **Reports (`reports/`):** Every time an analysis is completed via the web interface, the system saves two files locally:
  - A `.json` file with the structured data (Key metrics and chart data).
  - A `.md` file with the full text of the report generated by the AI.
- This allows for a "History" feature where users can consult previous analyses without spending API tokens.

## Execution Flow (Web)

1. The user enters a repository (e.g., `facebook/react`) in the Frontend.
2. The Frontend opens an SSE connection to `GET /api/analyze/stream` (or via POST if the client implements it that way, currently it is POST).
3. FastAPI initializes the LangChain Agent.
4. The Agent decides which tools to execute based on the prompt. It calls the GitHub APIs using the tools.
5. GitHub returns the requested data.
6. The Agent synthesizes the information, calculates DORA metrics estimates, and begins to generate the text in streaming.
7. The Backend transmits the generated tokens to the Frontend along with tool usage events (e.g., `tool_start`, `tool_end`).
8. Once finished, the Backend detects the `---JSON_START---` separator, extracts the executive information (structured), and saves the report to disk.
9. The Frontend closes the connection and displays the interactive results.
